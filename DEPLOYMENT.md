# Развёртывание TCMS — подробная инструкция для начинающего

Цель: получить публичную ссылку, по которой реальные пользователи смогут
зайти и работать в системе. Всё бесплатно (для небольшой внутренней команды).

## Что в итоге получится

| Слой | Сервис | Зачем |
|---|---|---|
| Код | GitHub | ✅ уже сделано — репозиторий `engservicesalexey2025-netizen/TCMS` |
| База данных | Neon | хранит все данные (сотрудники, проекты и т.д.) |
| Файлы (аттестаты/документы) | Supabase Storage | хранит загружаемые PDF |
| Backend (сервер приложения) | Render | обрабатывает запросы, обращается к базе |
| Frontend (сайт, который видят пользователи) | Vercel | то, что откроется по ссылке |

Компромисс бесплатного плана: backend на Render «засыпает» после 15 минут
без обращений, первый запрос после этого грузится 30–60 секунд — дальше
работает быстро. Для внутреннего инструмента это обычно некритично.

Каждый раздел ниже — это отдельный сайт, на котором нужно один раз
зарегистрироваться (или войти через GitHub) и один раз всё настроить.
Порядок важен — соблюдайте именно такую последовательность (1 → 2 → 3 → 4),
потому что на каждом следующем шаге нужны данные с предыдущего.

---

## Шаг 1. Neon — база данных

1. Откройте [neon.tech](https://neon.tech) → **Sign Up** (можно войти через
   GitHub — так проще всего, один клик).
2. После входа Neon предложит создать первый проект — **Create a project**.
   - Название — любое, например `tcms`.
   - Регион — любой ближайший к вам.
   - Postgres версия — оставьте по умолчанию.
3. После создания откроется страница проекта с разделом **Connection
   Details** (или «Connect»). Там будет строка вида:
   ```
   postgresql://neondb_owner:AbCdEf123456@ep-cool-name-12345.eu-central-1.aws.neon.tech/neondb?sslmode=require
   ```
   **Обязательно** выберите вариант **Pooled connection** (переключатель или
   выпадающий список рядом со строкой подключения — обычно подписан
   «Pooled connection» / «Connection pooling»).
4. Скопируйте эту строку в блокнот — она понадобится в Шаге 3. Но её нужно
   слегка изменить: в начале вместо `postgresql://` напишите
   `postgresql+psycopg://` (наше приложение использует именно такой формат).
   Итоговая строка должна выглядеть так:
   ```
   postgresql+psycopg://neondb_owner:AbCdEf123456@ep-cool-name-12345.eu-central-1.aws.neon.tech/neondb?sslmode=require
   ```

✅ Готово. Сохраните эту строку — назовём её **DATABASE_URL**.

---

## Шаг 2. Supabase Storage — хранилище файлов

Cloudflare R2 требует привязать карту даже на бесплатном тарифе — вместо
него используем Supabase Storage: тоже бесплатное S3-совместимое
хранилище, но без карты при регистрации.

1. Откройте [supabase.com](https://supabase.com) → **Start your project** →
   войдите через **GitHub** (карта не требуется).
2. **New Project**:
   - Организация — создастся автоматически при первом входе.
   - Имя проекта — например `tcms`.
   - Database Password — придумайте и **сохраните** (это пароль к
     Postgres внутри Supabase — нам он не понадобится, мы используем
     только файловое хранилище этого проекта, базу данных оставляем на
     Neon, но пароль всё равно нужно задать при создании проекта).
   - Регион — любой ближайший.
   - Тариф — **Free**.
3. Дождитесь создания проекта (1–2 минуты).
4. В левом меню откройте **Storage** → **Create a new bucket**:
   - Имя — `tcms-storage`.
   - Public bucket — **выключено** (оставьте приватным).
5. Откройте **Storage → Settings** (или значок настроек рядом с разделом
   Storage) → найдите блок **S3 Connection** / **Connection info**. Там
   будут:
   - **Endpoint** — адрес вида `https://<project-ref>.supabase.co/storage/v1/s3`
   - **Region** — обычно `us-east-1` (или указанный там регион).
6. Там же нажмите **New access key** (или «Create access key» в этом
   блоке) — получите:
   - `Access Key ID`
   - `Secret Access Key`

   **Скопируйте всё сразу в блокнот** — Secret Access Key повторно
   посмотреть будет нельзя, только создать новый.

✅ Готово. У вас теперь есть 4 значения для следующего шага:
`S3_ENDPOINT_URL` (endpoint), `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`,
`S3_BUCKET_NAME` (= `tcms-storage`).

## Шаг 3. Render — backend (сервер)

1. Откройте [render.com](https://render.com) → **Get Started** → войдите
   через **GitHub** (это упростит подключение репозитория).
2. На главной странице нажмите **New +** → **Web Service**.
3. Render попросит выбрать репозиторий — найдите и подключите
   `engservicesalexey2025-netizen/TCMS` (если репозиторий не виден, нажмите
   **Configure account** и разрешите Render доступ к нему на GitHub).
4. На экране настройки сервиса:
   - **Name** — например `tcms-backend`.
   - **Root Directory** — впишите `backend`.
   - **Environment / Runtime** — выберите **Docker**.
   - **Instance Type** — **Free**.
5. Ниже — раздел **Environment Variables** (переменные окружения). Нажмите
   **Add Environment Variable** и добавьте по одной все строки из таблицы:

   | Ключ | Значение |
   |---|---|
   | `DATABASE_URL` | строка из Шага 1 |
   | `SECRET_KEY` | любая длинная случайная строка (например, 40+ случайных символов/цифр — просто придумайте или сгенерируйте на [randomkeygen.com](https://randomkeygen.com)) |
   | `CORS_ORIGINS` | пока впишите `["http://localhost:5173"]` — вернёмся к этому в Шаге 4 |
   | `S3_ENDPOINT_URL` | endpoint из Шага 2 |
   | `S3_ACCESS_KEY_ID` | Access Key ID из Шага 2 |
   | `S3_SECRET_ACCESS_KEY` | Secret Access Key из Шага 2 |
   | `S3_BUCKET_NAME` | `tcms-storage` |
   | `SEED_ADMIN_LOGIN` | придумайте логин для главного администратора, например `admin` |
   | `SEED_ADMIN_EMAIL` | ваш настоящий email |
   | `SEED_ADMIN_PASSWORD` | придумайте надёжный пароль — **запишите его**, он понадобится для первого входа |

6. Найдите поле **Docker Command** (иногда спрятано под «Advanced» —
   разверните этот раздел) и впишите туда ровно это (без кавычек и `&&` —
   поле Render не поддерживает их, поэтому вся логика вынесена в файл
   `backend/start.sh`):
   ```
   sh start.sh
   ```
   Скрипт `start.sh` при каждом запуске сам обновляет структуру базы данных
   (`alembic upgrade head`), создаёт администратора (`python -m app.seed`,
   безопасно перезапускать многократно — не создаёт дубликаты), а затем
   запускает сервер.
7. Нажмите **Create Web Service**. Начнётся сборка — первый раз занимает
   5–10 минут. Следить за прогрессом можно во вкладке **Logs**.
8. Когда статус сервиса станет **Live** (зелёный) — вверху страницы будет
   ссылка вида `https://tcms-backend-xxxx.onrender.com`. **Скопируйте её** —
   понадобится в следующем шаге.
9. Проверка: откройте `https://tcms-backend-xxxx.onrender.com/health` в
   браузере — должно показать `{"status":"ok"}`. Если видите ошибку — во
   вкладке **Logs** будет текст ошибки, пришлите его мне.

✅ Готово. Backend работает. Сохраните ссылку на него — назовём её
**BACKEND_URL**.

## Шаг 4. Vercel — frontend (то, что увидят пользователи)

1. Откройте [vercel.com/new](https://vercel.com/new) → войдите через GitHub.
2. **Import Project** → найдите репозиторий `TCMS` → **Import**.
3. На экране настройки:
   - **Framework Preset** — должен определиться сам как **Vite**. Если нет
     — выберите вручную.
   - **Root Directory** — нажмите **Edit** рядом и укажите `frontend`. Это
     самый важный пункт — без него Vercel попытается собрать весь
     репозиторий целиком и выдаст ошибку (это и была ваша прошлая ошибка).
   - **Build Command** — оставьте по умолчанию (`npm run build` /
     `vite build`).
   - **Output Directory** — оставьте по умолчанию (`dist`).
4. Разверните **Environment Variables** и добавьте:

   | Ключ | Значение |
   |---|---|
   | `VITE_API_BASE_URL` | `BACKEND_URL` из Шага 3 + `/api/v1`, например: `https://tcms-backend-xxxx.onrender.com/api/v1` |

5. Нажмите **Deploy**. Сборка занимает 1–2 минуты.
6. После успешного деплоя Vercel покажет домен вида
   `https://tcms-xxxx.vercel.app` — это и есть **ссылка для пользователей**.
7. **Важный последний шаг** — вернитесь в Render (Шаг 3) → ваш сервис →
   **Environment** → отредактируйте `CORS_ORIGINS`, указав точный адрес из
   пункта 6:
   ```
   ["https://tcms-xxxx.vercel.app"]
   ```
   Сохраните — Render автоматически перезапустит сервис с новым значением.

✅ Готово. Сайт доступен по ссылке из пункта 6.

---

## Шаг 5. Финальная проверка

1. Откройте ссылку из Шага 4 (`https://tcms-xxxx.vercel.app`) в браузере.
2. Войдите под логином/паролем, которые вы придумали в Шаге 3
   (`SEED_ADMIN_LOGIN` / `SEED_ADMIN_PASSWORD`).
3. Если первый вход долго грузится (до минуты) — это нормально, backend
   «просыпается» после простоя.
4. Пройдитесь по разделам — Сотрудники, Проекты, KPI, Заявки на доступ —
   убедитесь, что всё открывается.
5. Загрузите тестовый PDF-аттестат сотруднику и скачайте его обратно —
   проверка, что файловое хранилище (Supabase Storage) работает.

Если что-то не открывается или выдаёт ошибку — пришлите мне точный текст
ошибки (из браузера или из вкладки Logs на Render/Vercel), разберёмся.

## Что дальше

- Ссылку `https://tcms-xxxx.vercel.app` можно давать пользователям.
- Новые пользователи получают доступ через раздел «Заявка на доступ» на
  странице входа — вы одобряете заявки в разделе «Заявки на доступ» под
  своим админ-логином.
- Каждый `git push` в GitHub автоматически обновляет и backend (Render), и
  frontend (Vercel) — доразработка (например, модуль «Организационная
  структура») будет разворачиваться сама после push.
